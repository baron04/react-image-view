# docs-site

The documentation site: [Astro Starlight](https://starlight.astro.build),
chosen over a React-app-with-static-export (the original build used
Fumadocs/Next.js) specifically because it's a genuine markdown-to-HTML SSG —
pages ship with near-zero client JS by default, there's no hydration layer to
carry, and search (Pagefind) indexes the built HTML directly rather than
needing a runtime service.

Content lives in `src/content/docs/*.mdx`; sidebar order is hand-listed in
`astro.config.mjs` rather than autogenerated, since the five pages have a
deliberate reading order.

## Commands

```bash
pnpm dev              # localhost:4321, from this directory
pnpm --dir docs-site dev   # same, from the repo root

pnpm build            # → dist/, resolves from `/` (local/preview)
GITHUB_PAGES=true pnpm build  # → dist/, resolves from /react-img-view/
```

The `GITHUB_PAGES` env var is what `astro.config.mjs` checks to decide
whether to prefix every route with `/react-img-view/` — GitHub Pages
serves a project site from a subpath, a local build doesn't. CI sets it;
running `pnpm build` by hand without it will not match what deploys.

## A real gotcha worth knowing before touching internal links

Starlight's base-path rewriting only reaches its **own** generated
navigation (the sidebar, prev/next pagination) — confirmed by building with
`GITHUB_PAGES=true` and grepping the output. Neither a literal
`[text](/installation/)` markdown link nor a component's `href` prop (even
Starlight's own `<LinkCard href>`) gets touched by it; both ship the bare,
unprefixed path if written that way. **Every internal cross-link in this
site's content is a relative path** (`../installation/`, `../`, not
`/installation/`) specifically to route around this — a relative path
resolves against the current page's own already-correct URL by ordinary
browser rules and needs no framework cooperation at all. Keep new internal
links relative, and verify with the same grep-the-build-output method if in
doubt — this was checked empirically twice in this repo's history and
disagreed with the docs both times, so don't take the framework's behaviour
here on faith either.
