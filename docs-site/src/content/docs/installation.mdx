## Requirements

React 18 or 19, and a browser environment — the package renders
`"use client"` and needs `document` at runtime (SSR is fine; nothing runs
until the viewer actually mounts).

## Install

```bash
npm install react-img-view
```

The package has no runtime dependencies of its own — the gesture engine,
the animation drivers, and the modal are all built on nothing but React and
the DOM.

## Styles

Every part ships unstyled by default: behaviour and `data-*` state only.
Two ways to get a look:

### The shipped preset

```tsx
import 'react-img-view/styles.css';
```

CSS custom properties on `:root` and the dialog itself — never on an
ancestor class, since the viewer portals out of the tree and a class-scoped
rule wouldn't follow it. Override any of them:

```css
:root {
  --riv-accent: #0f766e;
  --riv-chrome: #ffffff;
  --riv-stage: #f4f4f5;
}
```

Dark mode follows `prefers-color-scheme` automatically; force one side with
`data-riv-theme="light"` or `data-riv-theme="dark"` on `:root` or the
dialog.

### The shadcn registry block

If the project already uses Tailwind and shadcn's conventions, install the
Tailwind-classed version instead — real source in your repo, editable like
any other component:

```bash
npx shadcn add https://baron04.github.io/react-img-view/r/image-view.json
```

See [Design & Registry](../design-and-registry/) for what that installs
and how it relates to the CSS preset.

### Neither

Every part takes `asChild` and forwards `data-*` state
(`data-active`, `data-boundary`, `data-phase`, `data-state`). Style from
scratch with plain CSS attribute selectors, Tailwind's `data-[active]:…`
variants, or your own design system's components — see
[Quick Start](../quick-start/) for a fully custom L3 composition.
