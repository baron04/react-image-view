## Single image

Wrap any element — the thumbnail can be a plain `<img>`, `next/image`,
`<picture>`, or a component from your own design system. `ImageView` only
attaches behaviour and a `ref`; it never renders an `<img>` of its own for
the trigger.

```tsx
import { ImageView } from 'react-img-view'
import 'react-img-view/styles.css'

function SingleImagePreview({ image }: { image: { thumb: string; full: string; name: string } }) {
  return (
    <ImageView src={image.full} alt={image.name} name={image.name}>
      <img src={image.thumb} alt={image.name} />
    </ImageView>
  )
}
```

## Several images, shared viewer

`Group` collects every `ImageView` beneath it into one set. Clicking any one
opens the viewer positioned on that image, with arrow keys and swipe moving
between the rest. No `Content` is written here — `Group` supplies the same
polished default UI itself.

```tsx
import { ImageView } from 'react-img-view'
import 'react-img-view/styles.css'

function ImageList({ images }: { images: { src: string; name: string }[] }) {
  return (
    <ImageView.Group images={images}>
      <div className="grid grid-cols-4 gap-3">
        {images.map((image, i) => (
          <ImageView key={image.src} index={i} {...image}>
            <img src={image.src} alt={image.name} className="h-24 w-full object-cover" />
          </ImageView>
        ))}
      </div>
    </ImageView.Group>
  )
}
```

<Aside title="Pass width and height when you know them">
  `ImageItem` takes optional `width`/`height`. Supplying them skips a measurement round-trip, so the
  first frame is drawn at the right size instead of being corrected a frame later.
</Aside>

### Turning on the counter or the thumbnail strip

Both are off by default — for a short set, the arrows say enough.
Turn them on for a longer set, where the arrows alone do not say
enough:

```tsx
<ImageView.Group images={images}>
  {/* triggers */}
  <ImageView.DefaultContent counter thumbnails />
</ImageView.Group>
```

## Imperative API

Use the imperative API when you do not want to manage `open` and `index`
yourself:

```tsx
import { ImagePreview } from 'react-img-view/imperative'

function ViewButton({ images }) {
  return <button onClick={() => ImagePreview.open({ images, index: 2 })}>View image 3</button>
}
```

Pass the images and initial index to `open()`. Calling it again replaces the
current viewer. It returns a handle with `close()`, `go()`, `next()`, and
`prev()`; `ImagePreview.close()` closes whichever function-style viewer is
active. The viewer cleans itself up after closing.

An imperative call has no corresponding thumbnail element, so the viewer opens
directly without the thumbnail-to-image transition.

## Controlled open state

Open the viewer from anywhere else in the app — a "View" button in a table
row, say — by controlling `open` and `index` yourself. Prefer this form when
the surrounding component also needs to own those values:

```tsx
const [open, setOpen] = useState(false);
const [index, setIndex] = useState(0);

<ImageView.Group
  images={images}
  open={open}
  index={index}
  onOpenChange={setOpen}
  onIndexChange={setIndex}
>
  {/* triggers are optional when you open it programmatically */}
</ImageView.Group>

<Button onClick={() => { setIndex(2); setOpen(true); }}>
  View image 3
</Button>
```

## Full composition

Build your own layout from the same parts `DefaultContent` uses. Controls and
layout regions take `asChild`; `ImageView` always reuses its child. Every control
publishes `data-active` / `data-boundary` / `data-disabled` for styling.

Keep `Content` or `DefaultContent` as a direct child of the main-entry `Group`.
That is the boundary it checks before deciding whether to append the preset.

```tsx
import * as Viewer from 'react-img-view/primitives'

function CustomViewer({ images }) {
  return (
    <Viewer.Group images={images}>
      {images.map((image, i) => (
        <Viewer.ImageView key={image.src} index={i} {...image}>
          <img src={image.src} alt={image.alt} />
        </Viewer.ImageView>
      ))}

      <Viewer.Content className="riv-dialog">
        <Viewer.Header className="riv-header">
          <Viewer.Close>Close</Viewer.Close>
          <Viewer.Title />
          <Viewer.Download>Download</Viewer.Download>
        </Viewer.Header>

        <Viewer.Stage className="riv-stage">
          <Viewer.Image />
          <Viewer.Prev>‹</Viewer.Prev>
          <Viewer.Next>›</Viewer.Next>
          <Viewer.Loading>Loading…</Viewer.Loading>
          <Viewer.Error>
            {({ retry }) => (
              <div>
                <p>This image couldn&apos;t be loaded</p>
                <button onClick={retry}>Retry</button>
              </div>
            )}
          </Viewer.Error>

          <Viewer.Toolbar className="riv-toolbar">
            <Viewer.ZoomOut />
            <Viewer.ZoomIn />
            <Viewer.RotateLeft />
            <Viewer.RotateRight />
            <Viewer.FitToWindow />
            <Viewer.ActualSize />
          </Viewer.Toolbar>
        </Viewer.Stage>
      </Viewer.Content>
    </Viewer.Group>
  )
}
```

See [Customization](../customization/) for replacing individual
buttons, adding your own, and translating every string.

## Reading viewer state

`useViewer()` works from anywhere inside `Group` — a custom control, a
readout, an analytics hook:

```tsx
import { useViewer } from 'react-img-view/primitives'

function ZoomReadout() {
  const viewer = useViewer()
  return <span>{Math.round(viewer.scale * 100)}%</span>
}
```

See the [API reference](../api-reference/) for everything `useViewer()`
returns and every prop each part accepts.

## Keyboard shortcuts

| Key             | Action                |
| --------------- | --------------------- |
| `←` / `→`       | Previous / next image |
| `Home` / `End`  | First / last image    |
| `+` / `-`       | Zoom in / out         |
| `0`             | Fit to window         |
| `1`             | Actual size (1:1)     |
| `R` / `Shift+R` | Rotate right / left   |
| `Esc`           | Close                 |
