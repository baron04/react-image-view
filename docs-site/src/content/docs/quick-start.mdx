## Single image (L1)

Wrap any element — the thumbnail can be a plain `<img>`, `next/image`,
`<picture>`, or a component from your own design system. `ImageView` only
attaches behaviour and a `ref`; it never renders an `<img>` of its own for
the trigger.

```tsx
import { ImageView } from 'react-img-view';
import 'react-img-view/styles.css';

function ContractPreview({ file }: { file: { thumb: string; full: string; name: string } }) {
  return (
    <ImageView src={file.full} alt={file.name} name={file.name}>
      <img src={file.thumb} alt={file.name} />
    </ImageView>
  );
}
```

## Several images, shared viewer (L2)

`Root` collects every `Trigger` beneath it into one set; clicking any one
opens the viewer positioned on that image, with arrow keys and swipe moving
between the rest. No `Content` is written here — `Root` supplies the same
default UI itself.

```tsx
import { ImageView } from 'react-img-view';
import 'react-img-view/styles.css';

function Attachments({ files }: { files: { src: string; name: string }[] }) {
  return (
    <ImageView.Root images={files}>
      <div className="grid grid-cols-4 gap-3">
        {files.map((file, i) => (
          <ImageView.Trigger key={file.src} index={i} {...file}>
            <img src={file.src} alt={file.name} className="h-24 w-full object-cover" />
          </ImageView.Trigger>
        ))}
      </div>
    </ImageView.Root>
  );
}
```

### Controlled open state

Open the viewer from anywhere else in the app — a "查看" button in a table
row, say — by controlling `open` and `index` yourself:

```tsx
const [open, setOpen] = useState(false);
const [index, setIndex] = useState(0);

<ImageView.Root
  images={files}
  open={open}
  index={index}
  onOpenChange={setOpen}
  onIndexChange={setIndex}
>
  {/* triggers are optional when you open it programmatically */}
</ImageView.Root>

<Button onClick={() => { setIndex(2); setOpen(true); }}>
  查看第 3 张
</Button>
```

### Turning on the counter or the thumbnail strip

Both are off by default — see [the design decisions](../design-and-registry/#why-the-counter-and-thumbnails-are-off-by-default)
for why. Turn them on for a longer set (a gallery, a product's photos)
where the arrows alone don't say enough:

```tsx
<ImageView.Root images={files}>
  {/* triggers */}
  <ImageView.DefaultContent counter thumbnails />
</ImageView.Root>
```

## Full composition (L3)

Build your own layout from the same parts `DefaultContent` uses. Everything
takes `asChild` to keep your own element instead of the library's default
`<button>`/`<div>`, and every control publishes `data-active` /
`data-boundary` / `data-disabled` for styling.

```tsx
import { ImageView } from 'react-img-view';

<ImageView.Root images={files}>
  {/* triggers */}

  <ImageView.Content className="riv-dialog">
    <ImageView.Header className="riv-header">
      <ImageView.Close>关闭</ImageView.Close>
      <ImageView.Title />
      <ImageView.Download>下载</ImageView.Download>
    </ImageView.Header>

    <ImageView.Stage className="riv-stage">
      <ImageView.Image />
      <ImageView.Prev>‹</ImageView.Prev>
      <ImageView.Next>›</ImageView.Next>
      <ImageView.Loading>载入中…</ImageView.Loading>
      <ImageView.Error>
        {({ retry }) => (
          <div>
            <p>无法加载这张图片</p>
            <button onClick={retry}>重试</button>
          </div>
        )}
      </ImageView.Error>

      <ImageView.Toolbar className="riv-toolbar">
        <ImageView.ZoomOut />
        <ImageView.ZoomIn />
        <ImageView.RotateLeft />
        <ImageView.RotateRight />
        <ImageView.FitToWindow />
        <ImageView.ActualSize />
      </ImageView.Toolbar>
    </ImageView.Stage>
  </ImageView.Content>
</ImageView.Root>
```

## Reading viewer state

`useViewer()` works from anywhere inside `Root` — a custom control, a
readout, an analytics hook:

```tsx
import { useViewer } from 'react-img-view';

function ZoomReadout() {
  const viewer = useViewer();
  return <span>{Math.round(viewer.scale * 100)}%</span>;
}
```

See the [API reference](../api-reference/) for everything `useViewer()`
returns and every prop each part accepts.
