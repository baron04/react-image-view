## Single image (L1)

Wrap any element — the thumbnail can be a plain `<img>`, `next/image`,
`<picture>`, or a component from your own design system. `ImageView` only
attaches behaviour and a `ref`; it never renders an `<img>` of its own for
the trigger.

```tsx
import { ImageView } from 'react-img-view'
import 'react-img-view/styles.css'

function ContractPreview({ file }: { file: { thumb: string; full: string; name: string } }) {
  return (
    <ImageView src={file.full} alt={file.name} name={file.name}>
      <img src={file.thumb} alt={file.name} />
    </ImageView>
  )
}
```

## Several images, shared viewer (L2)

`Root` collects every `Trigger` beneath it into one set. Clicking any one
opens the viewer positioned on that image, with arrow keys and swipe moving
between the rest. No `Content` is written here — `Root` supplies the same
reviewed default UI itself.

```tsx
import { ImageView } from 'react-img-view'
import 'react-img-view/styles.css'

function Attachments({ files }: { files: { src: string; name: string }[] }) {
  return (
    <ImageView.Root images={files}>
      <div className="grid grid-cols-4 gap-3">
        {files.map((file, i) => (
          <ImageView.Trigger key={file.src} index={i} {...file}>
            <img src={file.src} alt={file.name} className="h-24 w-full object-cover" />
          </ImageView.Trigger>
        ))}
      </div>
    </ImageView.Root>
  )
}
```

<AttachmentsDemo client:load />

<Aside title="Pass width and height when you know them">
  `ImageItem` takes optional `width`/`height`. Supplying them skips a measurement round-trip, so the
  first frame is drawn at the right size instead of being corrected a frame later.
</Aside>

### Controlled open state

Open the viewer from anywhere else in the app — a "View" button in a table
row, say — by controlling `open` and `index` yourself:

```tsx
const [open, setOpen] = useState(false);
const [index, setIndex] = useState(0);

<ImageView.Root
  images={files}
  open={open}
  index={index}
  onOpenChange={setOpen}
  onIndexChange={setIndex}
>
  {/* triggers are optional when you open it programmatically */}
</ImageView.Root>

<Button onClick={() => { setIndex(2); setOpen(true); }}>
  View file 3
</Button>
```

### Turning on the counter or the thumbnail strip

Both are off by default — see
[the design decisions](../design-and-registry/) for why. Turn them on
for a longer set, where the arrows alone do not say enough:

```tsx
<ImageView.Root images={files}>
  {/* triggers */}
  <ImageView.DefaultContent counter thumbnails />
</ImageView.Root>
```

## Full composition (L3)

Build your own layout from the same parts `DefaultContent` uses. Controls and
layout regions take `asChild`; `Trigger` always reuses its child. Every control
publishes `data-active` / `data-boundary` / `data-disabled` for styling.

Keep `Content` or `DefaultContent` as a direct child of the main-entry `Root`.
That is the boundary it checks before deciding whether to append the preset.

```tsx
import * as ImageView from 'react-img-view/primitives'

function CustomViewer({ files }) {
  return (
    <ImageView.Root images={files}>
      {/* triggers */}

      <ImageView.Content className="riv-dialog">
        <ImageView.Header className="riv-header">
          <ImageView.Close>Close</ImageView.Close>
          <ImageView.Title />
          <ImageView.Download>Download</ImageView.Download>
        </ImageView.Header>

        <ImageView.Stage className="riv-stage">
          <ImageView.Image />
          <ImageView.Prev>‹</ImageView.Prev>
          <ImageView.Next>›</ImageView.Next>
          <ImageView.Loading>Loading…</ImageView.Loading>
          <ImageView.Error>
            {({ retry }) => (
              <div>
                <p>This image couldn&apos;t be loaded</p>
                <button onClick={retry}>Retry</button>
              </div>
            )}
          </ImageView.Error>

          <ImageView.Toolbar className="riv-toolbar">
            <ImageView.ZoomOut />
            <ImageView.ZoomIn />
            <ImageView.RotateLeft />
            <ImageView.RotateRight />
            <ImageView.FitToWindow />
            <ImageView.ActualSize />
          </ImageView.Toolbar>
        </ImageView.Stage>
      </ImageView.Content>
    </ImageView.Root>
  )
}
```

See [Customization](../customization/) for replacing individual
buttons, adding your own, and translating every string.

## Reading viewer state

`useViewer()` works from anywhere inside `Root` — a custom control, a
readout, an analytics hook:

```tsx
import { useViewer } from 'react-img-view/primitives'

function ZoomReadout() {
  const viewer = useViewer()
  return <span>{Math.round(viewer.scale * 100)}%</span>
}
```

See the [API reference](../api-reference/) for everything `useViewer()`
returns and every prop each part accepts.

## Keyboard shortcuts

| Key             | Action                |
| --------------- | --------------------- |
| `←` / `→`       | Previous / next image |
| `Home` / `End`  | First / last image    |
| `+` / `-`       | Zoom in / out         |
| `0`             | Fit to window         |
| `1`             | Actual size (1:1)     |
| `R` / `Shift+R` | Rotate right / left   |
| `Esc`           | Close                 |
