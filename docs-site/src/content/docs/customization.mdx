Three questions come up constantly, so they are answered in order here:
**how do I restyle it**, **how do I replace one button**, and **how do I add
something of my own**. Each has a smallest possible answer — you rarely need
to drop to full composition.

## How much do you need to change?

| You want to… | Reach for | Rebuild the UI? |
|---|---|---|
| Different colours, radii, spacing | [CSS custom properties](#1-css-custom-properties) | No |
| Restyle one part heavily | [`data-*` selectors](#2-data-attributes) | No |
| Swap a button's element or icon | [`asChild` / children](#3-aschild) | No |
| Add, remove, or reorder buttons | [Compose `DefaultContent` yourself](#4-compose-your-own-content) | Yes, but from the same parts |
| Add a keyboard shortcut or gesture rule | [Extensions](#5-extensions) | No |
| Translate the interface | [`labels`](#6-labels) | No |

## 1. CSS custom properties

The quickest change. The preset stylesheet reads everything from custom
properties, so overriding them restyles the whole viewer without touching a
selector.

```css
:root {
  --riv-accent: #0f766e;          /* focus rings, active control state */
  --riv-accent-surface: #ccfbf1;  /* active control background */
  --riv-chrome: #ffffff;          /* header and toolbar surface */
  --riv-stage: #f4f4f5;           /* area behind the image */
  --riv-ink: #18181b;             /* primary text and icons */
  --riv-ink-muted: #71717a;       /* secondary text */
  --riv-line: #e4e4e7;            /* borders and separators */
  --riv-hover: #f4f4f5;           /* control hover background */
  --riv-radius: 12px;             /* dialog corner radius */
  --riv-radius-toolbar: 10px;     /* toolbar corner radius */
}
```

Set them on `:root` or on the dialog itself — **not** on an ancestor class.
The viewer portals to `document.body`, so a rule scoped to a wrapper class
never reaches it. That is also why dark mode is wired to
`prefers-color-scheme` plus an explicit `data-riv-theme="light" | "dark"`
on `:root` or the dialog, rather than to a `.dark` class on some container.

## 2. Data attributes

Every part exposes its identity and state as `data-*`, so you can target it
with plain CSS or Tailwind variants without knowing any class names.

```css
/* One specific control */
[data-image-view-control='actual-size'] { font-variant-numeric: tabular-nums; }

/* State, not a class */
[data-image-view-control][data-active] { outline: 2px solid var(--riv-accent); }
[data-image-view-control][data-boundary] { opacity: 0.35; }

/* Regions */
[data-image-view-region='toolbar'] { backdrop-filter: blur(8px); }
[data-image-view-stage][data-phase='dismissing'] { cursor: grabbing; }
```

```tsx
// The same hooks in Tailwind
<ImageView.ActualSize className="data-[active]:bg-teal-100 data-[boundary]:opacity-40" />
```

The full set: `data-image-view` (dialog), `-stage`, `-viewport`, `-track`,
`-slide`, `-trigger`, `-title`, `-counter`, `-loading`, `-error`,
`-thumbnails`, `-thumb`, `-region="header|toolbar|footer"`, and
`-control="close|prev|next|zoom-in|zoom-out|rotate-left|rotate-right|fit|actual-size|download|retry"`.
State: `data-active`, `data-boundary`, `data-disabled`, `data-current`,
`data-phase`, `data-state`, `data-closing`.

## 3. `asChild`

To change a control's **element** — to use your design system's button, or
wrap it in a tooltip — pass `asChild` and provide the element yourself. The
control merges its behaviour, `aria-label`, and `data-*` onto your child
instead of rendering its own `<button>`.

```tsx
import { Button } from '@/components/ui/button';

<ImageView.ZoomIn asChild>
  <Button variant="ghost" size="icon">
    <PlusIcon />
  </Button>
</ImageView.ZoomIn>
```

<Aside type="caution" title="An asChild child must forward props and ref">
  Controls pass their click handler, the ref the animation is measured from,
  and their `data-*` by cloning the child through a Slot. A child component
  that drops unknown props swallows all of it — the thumbnail renders
  perfectly and simply does nothing when clicked, with no error. Use
  `React.forwardRef` and spread `...rest` onto a real DOM node.
</Aside>

To change only the **icon or text**, pass children — no `asChild` needed:

```tsx
<ImageView.Close>
  <XIcon /> Dismiss
</ImageView.Close>
```

## 4. Compose your own content

To add, remove, or reorder buttons, write the shell yourself. This is the
same set of parts `DefaultContent` uses — there is no private assembly
underneath it — so you are not giving anything up by opting in.

The rule: **if `Root` finds an `<ImageView.Content>` (or a
`<DefaultContent>`) among its children, it adds nothing of its own.**
Otherwise it appends the default UI. So composing is simply writing the
`Content` yourself.

```tsx
<ImageView.Root images={files}>
  {/* triggers */}

  <ImageView.Content className="riv-dialog">
    <ImageView.Header className="riv-header">
      <ImageView.Close>Close</ImageView.Close>
      <ImageView.Title />
      <ImageView.Counter />
      <span className="flex-1" />
      {/* A button of your own, right next to the built-ins */}
      <button onClick={() => print()}>Print</button>
      <ImageView.Download>Download</ImageView.Download>
    </ImageView.Header>

    <ImageView.Stage className="riv-stage">
      <ImageView.Image />
      <ImageView.Prev>‹</ImageView.Prev>
      <ImageView.Next>›</ImageView.Next>
      <ImageView.Loading>Loading…</ImageView.Loading>
      <ImageView.Error>
        {({ retry }) => (
          <div>
            <p>This image couldn&apos;t be loaded</p>
            <button onClick={retry}>Retry</button>
          </div>
        )}
      </ImageView.Error>

      {/* Rotate dropped, zoom kept, order changed — nothing is mandatory */}
      <ImageView.Toolbar className="riv-toolbar">
        <ImageView.ZoomOut />
        <ImageView.ZoomIn />
        <ImageView.FitToWindow />
        <ImageView.ActualSize />
      </ImageView.Toolbar>
    </ImageView.Stage>
  </ImageView.Content>
</ImageView.Root>
```

<Aside title="Keeping most of the default">
  If you only want to toggle the built-in options rather than rebuild, render
  `<ImageView.DefaultContent counter thumbnails />` explicitly. Placing it
  yourself is what stops `Root` appending a second copy.
</Aside>

### Driving the viewer from your own UI

`useViewer()` works anywhere inside `Root`, so a custom control is just a
button that calls the API.

```tsx
import { useViewer } from 'react-img-view';

function ZoomReadout() {
  const viewer = useViewer();
  return <span>{Math.round(viewer.scale * 100)}%</span>;
}

function PrintButton() {
  const viewer = useViewer();
  return <button onClick={() => window.print()} disabled={viewer.status !== 'ready'}>Print</button>;
}
```

Opening it from somewhere else entirely — a table row's "View" button —
means controlling `open` and `index` yourself:

```tsx
const [open, setOpen] = useState(false);
const [index, setIndex] = useState(0);

<ImageView.Root
  images={files}
  open={open}
  index={index}
  onOpenChange={setOpen}
  onIndexChange={setIndex}
/>

<Button onClick={() => { setIndex(2); setOpen(true); }}>View file 3</Button>
```

## 5. Extensions

For behaviour that composition cannot reach — claiming a key, vetoing a
gesture — pass an extension. Returning `true` marks the event consumed so
the built-in handling is skipped.

```tsx
const pageWithSpace = {
  name: 'space-pages',
  onKeyDown(event, api) {
    if (event.key !== ' ') return;
    event.shiftKey ? api.prev() : api.next();
    return true; // handled; don't fall through
  },
};

<ImageView.Root images={files} extensions={[pageWithSpace]} />
```

`onGesture(phase, api)` receives `'start' | 'move' | 'end'` for the same
purpose on the pointer side. Anything that needs to *render* belongs in the
tree as a child instead — extensions are deliberately two hooks, not a
plugin system.

## 6. Labels

Every user-facing string — visible text and `aria-label` alike — comes from
one record, English by default. Pass `labels` to translate the interface;
it merges field by field, so overriding one leaves the rest alone.

```tsx
<ImageView.Root
  images={files}
  labels={{ close: 'Fermer', download: 'Télécharger', zoomIn: 'Agrandir' }}
/>
```

Custom controls should read the same set with `useLabels()`, so an app
translates one place rather than two:

```tsx
import { useLabels } from 'react-img-view';

function MyClose() {
  const labels = useLabels();
  return <ImageView.Close aria-label={labels.close}>{labels.close}</ImageView.Close>;
}
```

See [`ViewerLabels`](../api-reference/#viewerlabels) for the full list of keys.
